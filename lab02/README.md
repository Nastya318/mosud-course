# Практическая работа №2. Множества и мультимножества в SQL

- **Вариант:** 6 (Штат X = ES, Штат Y = RJ)

## Мощности множеств
| Множество | Количество уникальных товаров (count DISTINCT) |
| :--- | :--- |
| A (клиенты из ES) | [1648] |
| B (клиенты из RJ) | [7672] |
| A ∪ B (UNION) | [8575] |
| A ∪ B (UNION ALL) | [9320] |
| A ∩ B (INTERSECT) | [745] |
| A − B (EXCEPT) | [903] |
| B − A (EXCEPT) | [6927] |

## Вывод о дубликатах
При использовании `UNION ALL` количество строк больше, чем при `UNION`, потому что товары, которые одновременно покупали клиенты и из ES, и из RJ, попадают в результат дважды. Операции `UNION`, `INTERSECT` и `EXCEPT` автоматически удаляют дубликаты, приводя результат к классическому математическому множеству.


Какие операции возвращают множество, а какие мультимножество?

Операции UNION, INTERSECT и EXCEPT (без суффикса ALL) возвращают МНОЖЕСТВО,так как СУБД автоматически удаляет дубликаты строк.
Операции UNION ALL, INTERSECT ALL и EXCEPT ALL (поддерживаются в PostgreSQL) возвращают Мультимножество, сохраняя все повторяющиеся строки.
Обычный SELECT без DISTINCT также возвращает мультимножество.
